# Word 指令占位符模板解析优化设计

## 背景

当前模板解析器可以识别 `{{板块名称}}`、Word 内置 `Heading*` 样式以及少量固定标题，但用户上传的实际模板使用自定义 `Weekly *` 样式和 `【填写……】`、`【概述……】` 等指令标记。解析结果因此为空，模板确认页没有板块，确认按钮保持禁用。

## 目标

1. 将 Word 中每一个明确的中文方括号填充指令识别为独立生成项。
2. 只替换指令标记，保留模板标题、前缀文字、段落样式及其他内容。
3. 使用所在一级章节、分组标题和字段标签生成稳定、可读且唯一的板块名称。
4. 将方括号内的文字保存为生成指令，供本地大模型生成对应内容。
5. 保持现有 `{{板块名称}}`、标题样式和固定标题识别逻辑兼容。
6. 模板没有识别结果时，在页面显示明确原因，而不是只提供一个无法点击的按钮。

## 非目标

- 不修改用户上传的原始 Word 模板。
- 不把所有 `【……】` 内容都当成占位符。
- 不增加手工创建或拖拽调整模板板块的界面。
- 不重构模板写入、分析流水线或任务状态机。

## 识别规则

解析器新增“指令占位符”规则，只识别内容以以下形式开头的中文方括号：

- `【填写……】`
- `【概述……】`
- `【无；如有，请填写……】`

普通说明、编号或业务正文中的其他方括号不参与识别。

每个命中的完整方括号文本作为 `locator.token`。生成 Word 时仅替换该 token，因此同一段落中的多个标记可以分别写入，标记前后的文字保持不变。

## 板块命名

解析器按文档顺序维护两级上下文：

- `Weekly Section` 样式：一级章节，例如“二、本周重点工作”。
- `Weekly Group` 样式：组名，例如“业务连续性”。

字段名称优先取标记前紧邻的文字，并去除末尾逗号、冒号、序号和多余空白。例如：

- `业务连续性：【概述……】` → `本周工作概述 / 业务连续性`
- `组件扩容与迁移，【填写……】` → `本周重点工作 / 业务连续性 / 组件扩容与迁移`
- 仅有 `【无；如有，请填写……】` → `问题及风险点`
- `1. 【填写下周计划一……】` → `下周重点工作 / 计划一`

一级章节名称去除中文序号前缀。最终名称按“一级章节 / 分组 / 字段”组合，并省略重复层级。若仍有重名，按文档顺序追加 `（2）`、`（3）`，确保名称和 ID 都稳定唯一。

## 数据结构

`RecognitionMethod` 新增 `instruction_placeholder`。指令占位符的字段如下：

- `name`：根据上下文生成的唯一板块名称。
- `method`：`instruction_placeholder`。
- `confidence`：`0.95`，属于明确模板标记，不要求用户逐项勾选低置信度确认。
- `locator.part`：所在正文、页眉或页脚逻辑分区。
- `locator.paragraph_index`：标记所在段落位置。
- `locator.token`：完整中文方括号标记。
- `instruction`：去除外层方括号后的指令文字。

现有显式 `{{……}}` 占位符仍保持 `1.0` 置信度及原有命名。去重时不改变旧模板行为。

## 页面行为

模板确认页继续以“存在至少一个板块，且所有低置信度板块已确认”为按钮启用条件。

当接口成功返回空数组时，板块列表区域显示：

> 模板中没有可识别的填写位置。请在 Word 中使用 `{{板块名称}}`，或使用 `【填写……】`、`【概述……】` 标记需要生成的内容。

按钮继续保持禁用，避免提交必然失败的确认请求。

## 错误处理

- 不完整的中文方括号不识别，也不报错。
- 不含明确指令关键词的方括号不识别。
- 识别结果仍为空时由页面显示可操作提示。
- 写入阶段找不到 token 时继续使用现有 `PLACEHOLDER_MISSING` 错误，防止静默破坏文档。

## 测试与验收

1. 解析测试覆盖同段多个指令标记、自定义章节和分组样式、无前缀风险标记、下周计划及重名消歧。
2. 写入测试证明多个中文指令 token 可以分别替换，且前缀文字保留。
3. 旧有 `{{……}}`、页眉页脚、表格和标题识别测试保持通过。
4. 前端测试覆盖空数组提示、按钮禁用以及有板块时正常展示。
5. 使用用户当前模板执行解析，结果数量大于零、名称唯一、token 唯一。
6. 重新识别当前任务后，页面出现模板板块，确认按钮处于可用状态。
